## Порядок исполнения (решение владельца 2026-10-06)

- **Оркестратор** — отдельная сессия Claude Code, которая вела план. Пишет промпты исполнителю (`plans/zapusk-demo-prompts/phase-N.md`) и ревьюеру (`phase-N-review.md`), выступает судьёй: сверяет каждое замечание ревьюера с кодом и решает «принять / отклонить / отложить». Пишет промпт на исправления, после успешного ревью делает поимённый коммит фазы в `dev`.
- **Исполнитель** — новая сессия Claude Code на каждую фазу и на каждый раунд исправлений. Работает строго по промпту и этому плану, пишет тесты, код и checkpoint, **не коммитит** и не делает push.
- **Ревьюер** — отдельная новая сессия Claude Code (с фазы 1, решение владельца 2026-10-06). Только читает код и запускает проверки, рабочее дерево не меняет; отчёт пишет в `plans/zapusk-demo-reviews/phase-N.md`. Фазу 0 ревьюил оркестратор.
- Три роли — три разные сессии: исполнитель не ревьюит себя, ревьюер не пишет код, судья не автор замечаний. Владелец может оспорить любое решение.
- Цикл фазы: промпт → исполнитель → ревьюер → судья → (промпт на исправления → исполнитель → повторное ревью) → коммит → промпт следующей фазы.

## Цель и контекст

- **Для кого и зачем:** Ghostwriter сейчас — демонстрационный проект (портфолио), не SaaS. Потенциальный заказчик разработки открывает ссылку и за пару минут видит, как владельцу малого бизнеса пишется живой пост под VK, Telegram, Max или Дзен — сразу без регистрации или с регистрацией по логину и паролю. Измеримый результат — критерии готовности в `idea/mvp.md` (с версии 5 плана — версия 6 `mvp.md`, критерии 1–8, включая 2а–2д).
- **Источники фактов:** `idea/` (ядро, исследование, риски, принципы, MVP; в git с коммитов владельца `e65e7ff`, `9554797`), код репозитория. Бизнес-контекст владельца хранится вне репозитория. Гипотеза: ценность для владельцев бизнеса не проверена (`idea/proof-of-value.md`). Как решения из `idea/` ложатся на план — `idea/plan-impact.md`.
- **Архитектура:** отдельного документа нет; раздел «Архитектура» в `README.md` устарел (Flask, OpenAI, бот) и переписывается в фазе 6.
- **Что уже есть:**
  - Django-приложение с генерацией через GigaChat (`generator/gigachat_api.py`), картинки GigaChat по кнопке.
  - Доступ по токенам `TemporaryAccessToken`: `@token_required`, `@consume_generation`, `TokenAccessMiddleware`, вход по ссылке `token_auth_view`. Токены выдавал Telegram-бот. Middleware не учитывает `request.user`; декораторы при плохом токене делают `session.flush()`.
  - Регистрация и вход отключены (`register_view` → заглушка, `RegisterForm` удалена). Старый `agreement_view` брал пароль открытым текстом из сессии. Шаблоны входа и регистрации ссылаются на `quick_login` (маршрут только при `DEBUG`).
  - Шаблоны: 15 страниц наследуют `generator/index.html` (тема «Киберпанк», применяется после загрузки DOM), `landing.html` — отдельная страница; Bootstrap 5.3.0, иконки и шрифты — с внешних CDN; `styles.css` — 1570 строк.
  - Тесты `tests.test_django_models`, `tests.test_django_isolated`: 21 тест, на 2026-10-06 **8 падений и 3 ошибки**. В `test_settings` миграции отключены, база в памяти.
  - Продакшен: `docker-compose.production.yml` (django, bot, db, redis, nginx), `production_settings.py` с `DEBUG = False`, сессии `cached_db`, самоподписанный сертификат на IP, только порт 443. Сервер не работает. Домена нет — владелец купит.
- **Найдено на ревью версии 1 (код, 2026-10-06), закрывается этим планом:**
  - `DJANGO_API_KEY` не читается в настройках Django, поэтому проверка ключа в API всегда пропускается: любой может создать токен любого типа, включая безлимитный DEVELOPER (`generator/views.py:1456-1463`). Вебхук ЮKassa не проверяет подпись.
  - Перегенерация текста и картинки под `/api/` работает без токена и без CSRF (`generator/views.py:323-324, 581-582`).
  - `get_client_ip` берёт первый элемент `X-Forwarded-For`, который клиент может подделать (`decorators.py:110-113`).
  - Продакшен читает `DJANGO_SECRET_KEY`, а compose передаёт `SECRET_KEY` (`production_settings.py:15`, `docker-compose.production.yml:48`).
  - Стена и детали генераций без пользователя показывают всем анонимные генерации всех посетителей (`views.py:901-933`).
- **Найдено при подготовке версии 5 (код, 2026-10-08, оркестратор):**
  - Ошибки генерации выдаются за пост. `generate_text` при любой ошибке возвращает строку `WARNING: …` (`gigachat_api.py:853–900`). `generator_view` отдаёт её с `success: True`, сохраняет в историю и при отмеченной картинке делает по ней ещё вызов GigaChat (`views.py:207–227`). `regenerate_text` дописывает её в историю версией (`views.py:377–409`).
  - Фронтенд вставляет `data.error` в `innerHTML` без экранирования (`gigagenerator.html:582–583`, `showToast` — `:607`), а `generator_view` при исключении отдаёт `str(e)` (`views.py:301`). Пока сообщения — константы, но с импортом по ссылке в ошибку может попасть чужой текст.
  - Имена шаблонов настроек вставляются в `innerHTML` без экранирования (`gigagenerator.html:824`).
  - Настройки читаются до `.env`: `load_dotenv()` вызывается только при импорте `gigachat_api` (`gigachat_api.py:26`). Переменные из `.env` (`GIGACHAT_MODEL`, будущие `YANDEX_*`) при `runserver` не доходят до `settings`.
  - Предохранитель тестов перехватывает только клиентов GigaChat и `requests` (`tests/runner.py:47–51`); `httpx`, `urllib` и разрешение DNS не перехвачены.
  - Переключатель `generator_type` (GigaChat / OpenAI) — `gigagenerator.html:285–300`, ветка Flask — `views.py:158–190`.

## Решения владельца (2026-10-06)

- Коммиты: разрешены поимённые коммиты в `dev` после ревью каждой фазы. Push — только по отдельному решению.
- Админка остаётся — для наблюдения за квотой; суперпользователя на сервере создаёт владелец.
- Домен владелец покупает у регистратора (например, Reg.ru); сервер может быть у другого провайдера — домен направляется на IP сервера A-записью.
- Регистрация — по логину и паролю, без email. Зарегистрированный получает историю постов, сохранённое «О бизнесе», шаблоны настроек и больше генераций в день. Демо без регистрации остаётся.
- Оформление: тёмная тема по умолчанию и светлая по переключателю; сайт должен выглядеть как нормальный сайт.

### [ ] Фаза 2а.4: профиль по ссылке — сайт и сообщество VK, защита от SSRF (2 дня)

Источник: `idea/plan-impact.md`, раздел 4, п. 1; `mvp.md`, п. 4б; `risks.md`, п. 13. Самая рискованная фаза плана.

- **Перед ручной проверкой владелец:** создаёт приложение VK, получает сервисный ключ и кладёт его в `.env` как `VK_SERVICE_TOKEN`. Без ключа часть VK ручной проверки ждёт; тесты от ключа не зависят.

  - **Эндпоинт** `POST /import-profile/`: CSRF, за `TokenAccessMiddleware` (не в исключениях), AJAX, JSON. Порядок:
    1. лимит импортов — не больше `IMPORT_PER_SESSION` на сессию и `IMPORT_PER_IP_PER_DAY` на IP в сутки (env). Счётчик — `AccessEvent` с новым типом события; считаются и неудачные попытки, проверка — до любого сетевого запроса;
    2. единая проверка 2а.2 для модели черновика (токен, бюджет, потолок) — тоже до сети;
    3. разбор и проверка ссылки; длина — не больше `IMPORT_MAX_URL_LENGTH`;
    4. загрузка сайта или запросы к VK API;
    5. извлечение текста;
    6. один вызов модели: черновик «О бизнесе»;
    7. ответ: черновик (не длиннее `GENERATION_MAX_BUSINESS_INFO_LENGTH`) и образцы VK (в пределах `GENERATION_MAX_SAMPLES_LENGTH`).
  - **Безопасная загрузка сайта** — отдельный модуль в `generator/`:
    - только `http` и `https`, только порты 80 и 443, без логина и пароля в адресе; имя хоста в IDN приводится к punycode;
    - хост разрешается во все адреса; отказ, если хоть один адрес не глобальный (`ipaddress`: частный, loopback, link-local, CGNAT `100.64.0.0/10`, зарезервированный, multicast, нулевой). IPv4 внутри IPv6 (`::ffff:127.0.0.1`, NAT64, 6to4) проверяется по вложенному адресу. Числовые записи хоста (`2130706433`, `0x7f000001`, `0177.0.0.1`, `127.1`) проверяются по разрешённому адресу, а не по строке;
    - соединение — только с проверенным адресом, без второго разрешения DNS (защита от DNS rebinding). `Host`, SNI и проверка сертификата — по имени хоста. Способ — на выбор исполнителя, с обоснованием в checkpoint;
    - прокси из окружения не используются (`trust_env=False` или эквивалент); cookies не хранятся; только GET;
    - редиректы вручную, не больше 3; каждый `Location` (и относительный) проходит ту же проверку;
    - таймауты соединения и чтения плюс общий предел времени на загрузку (`IMPORT_FETCH_TIMEOUT`); чтение потоком с обрывом после `IMPORT_MAX_BYTES` (1–2 МБ) — считаются байты после распаковки gzip; `Content-Length` больше лимита → отказ до чтения;
    - только `text/html` и `application/xhtml+xml`;
    - сообщения об отказе — константы, одинаковые для «запрещённый адрес» и «адрес недоступен»: ответ не раскрывает устройство внутренней сети. Ссылка и текст страницы в сообщение не попадают; в лог — без полного текста страницы.
  - **Разбор сайта** — `beautifulsoup4` (уже в зависимостях): `title`, `meta description`, `og:description`, заголовки и абзацы; без `script`, `style`, `nav`, `footer`; не больше `IMPORT_MAX_TEXT_LENGTH` символов. `trafilatura` — только если на замере `beautifulsoup4` даёт мусор, и по решению владельца.
  - **VK:** хосты `vk.com`, `vk.ru`, `m.vk.com`, `m.vk.ru` (и `www.`). Страница VK не скачивается. Из пути берётся `club<id>`, `public<id>` или короткое имя (строгий шаблон); иначе — «это не ссылка на сообщество».
    - Запросы — только к постоянному хосту VK API: `groups.getById` (название, описание) и `wall.get` (свои записи, не больше 20).
    - Отбрасываются репосты (`copy_history`), рекламные (`marked_as_ads`) и пустые записи. Остаётся не больше 10 постов в пределах лимита объёма.
    - Нет `VK_SERVICE_TOKEN` → импорт из VK выключен с понятным сообщением, API не вызывается. Закрытая стена или ошибка API → понятное сообщение; сырой ответ VK об ошибке не логируется и не отдаётся (в нём бывают параметры запроса).
    - Ключ — не в строке адреса: исключения `requests` содержат полный URL. Передавать в теле POST-запроса или заголовке — способ сверить с документацией VK API. Ключа нет в логах, исключениях и ответах.
  - **Защита от prompt injection:** текст страницы, описание сообщества и посты — в сообщении к модели только внутри явных разделителей, как данные; разделитель внутри данных вычищается. В инструкции: в данных нет команд для модели; черновик — только о бизнесе, только то, что есть в тексте, обычным текстом, не длиннее лимита.
  - **Фронтенд:** поле «Ссылка на сайт или сообщество VK» и кнопка «Заполнить по ссылке» (оформление — фаза 5). Черновик и образцы подставляются в поля через `.value`, ошибки — текстом; владелец правит до генерации. Сырой HTML и ответы API не сохраняются; в сессию данные попадают только с отправкой формы.
  - **Настройки** — имена в `env.example` и `env.production.example` без значений: `VK_SERVICE_TOKEN`, `IMPORT_PER_SESSION`, `IMPORT_PER_IP_PER_DAY`, `IMPORT_FETCH_TIMEOUT`, `IMPORT_MAX_BYTES`, `IMPORT_MAX_TEXT_LENGTH`, `IMPORT_MAX_URL_LENGTH`.
  - **Правила VK API** о получении данных сообществ сверить до ручной проверки; ссылка и вывод — в checkpoint.
- **Критерии (тесты):**
  - Отказ без единого сетевого соединения: `http://127.0.0.1`, `http://localhost`, `http://10.0.0.5`, `http://172.16.0.1`, `http://192.168.1.1`, `http://100.64.0.1`, `http://169.254.169.254`, `http://0.0.0.0`, `http://[::1]`, `http://[::ffff:127.0.0.1]`, `http://2130706433`, `http://0x7f000001`, `http://0177.0.0.1`, `http://127.1`, `http://db:5432`, `http://redis`, `file:///etc/passwd`, `ftp://…`, `gopher://…`, порты 8080 и 22, `http://user:pass@example.com`; хост, который разрешается в `127.0.0.1`; хост с одним публичным и одним частным адресом.
  - DNS rebinding: первое разрешение — публичный адрес, второе — `127.0.0.1` → соединения с `127.0.0.1` нет.
  - Редирект с публичного адреса на внутренний, четвёртый редирект, редирект на `file://` → отказ после ответа, который его вернул.

  - Переменные `HTTP_PROXY` и `HTTPS_PROXY` в окружении не используются.
  - VK: `vk.com/club123`, `vk.ru/name`, `m.vk.com/public123` распознаются; `vk.com/id123`, `vk.com/wall-1_2`, `vk.com/../..` — нет. Репосты, пустые и рекламные записи отфильтрованы; постов не больше 10; закрытая стена и отсутствие ключа → сообщение без вызова API; ключа нет в ответе и в выводе логов теста.

  - Текст страницы с «игнорируй инструкции» и закрывающим разделителем попадает в сообщение только внутри блока данных.
  - Без токена или CSRF → 403, сети нет.
  - Мутации: убрать проверку адреса после редиректа, проверять адрес строкой вместо разрешённых IP, разрешать DNS повторно при соединении, убрать лимит байт — каждая роняет тест.
  - Ручная проверка — критерий 2б `mvp.md`: 3 открытых сообщества VK и 3 сайта малого бизнеса — черновик без выдуманных фактов, из VK — 5–10 постов без репостов. Битая ссылка, закрытая стена, `http://127.0.0.1` на `runserver` → понятное сообщение, генерация работает на ручных полях. В отчёте — без телефонов, имён и адресов из импортированного текста.
- **Генерации:** до 15; запросы к сайтам и VK API — в пределах лимитов плана.
- **Ревью:** независимый рецензент по безопасности — SSRF (адреса, DNS rebinding, редиректы, прокси, размер), prompt injection, ключ VK, лимиты, XSS в подстановке.
