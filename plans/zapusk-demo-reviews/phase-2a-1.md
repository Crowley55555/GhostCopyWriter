### 1. `_WHOLE_WORDS` и `_INSTRUMENTAL_ONLY_STEMS` защищены эквивалентной стандартной логикой — мутации «вернуть к стандартной основе» на нынешних тестах не ловятся

- **Серьёзность:** мелочь.
- **Доказательство:**
  - `generator/gigachat_api.py:544` — `_WHOLE_WORDS = frozenset({'больше'})`. Мутация `_WHOLE_WORDS = frozenset()` + пересборка `_STOP_PATTERNS` (`mutations_stop.py` в scratchpad) — `test_bolshe_whole_word` остаётся зелёным: без «целого слова» для `больше` сработает ветка `_NOUN_ENDINGS`, которая даёт `больш(?:...|е|...)` — т.е. `больше\b` всё равно срабатывает для `Хотите узнать больше о зерне`, а на `Хотите узнать большое меню` ни один вариант окончания не даёт `\b` после `больш`+окончание (между `больш` и `о` нет границы, между `о` и `е` тоже), поэтому `[]` остаётся `[]`. Проверено запуском `tests.test_post_quality.StopPhrasesTests.test_bolshe_whole_word` под мутацией: `bad=0`.
  - `generator/gigachat_api.py:554` — `_INSTRUMENTAL_ONLY_STEMS = {'душой': ('душ', ('ой', 'ою'))}`. Мутация `_INSTRUMENTAL_ONLY_STEMS = {}` + пересборка `_STOP_PATTERNS` — `test_s_dushoy_instrumental_only` остаётся зелёным: `_NOUN_ENDINGS` не содержит `ем`, поэтому `с душем` не ловится и без исключения; на `с душевной музыкой` после `душ` стоит `е` + `в`, ни одно окончание из `_NOUN_ENDINGS` не даёт `\b`, поэтому ответ тоже `[]`. Проверено: `bad=0`.
- **Сценарий сбоя:** будущее добавление штампа или входа, где различие между «ловить все формы существительного» и «ловить только творительный» (или «только слово целиком») будет значимым, уронит продукт, а не тесты — регрессия пройдёт в прод и покажется только на живых постах. Пример: если позже появится проба `С душой студента…` — исходный код её поймает, а мутант «убрал `_INSTRUMENTAL_ONLY_STEMS`» — тоже (`душ`+`ой` в `_NOUN_ENDINGS`); но для входа вроде `с душе на вечерней прогулке` различие ещё могло бы прорасти, если бы автор убрал `_INSTRUMENTAL_ONLY_STEMS` и, скажем, оставил ветку с глагольными окончаниями.
- **Что изменить:** в `test_bolshe_whole_word` и `test_s_dushoy_instrumental_only` добавить одну-две пробы, которые отличают «целое слово/творительный» от стандартной логики `_NOUN_ENDINGS`. Варианты, которые закрывают мутацию:
  - для `больше`: `«Выдали заем большей суммы»` (без слов «хотите узнать» перед `больш…` штамп не ищется, поэтому проба не ловится) — лучше поменять: добавить тест отдельного шаблона `_stop_word_pattern('больше').pattern == 'больше'`;
  - для `с душой`: `assertEqual(_stop_word_pattern('душой'), re.escape('душ') + '(?:ой|ою)')` или полный pattern-тест через `_stop_phrase_pattern('с душой').pattern`.
- **Как проверить:** мутация «удалить `_WHOLE_WORDS` / `_INSTRUMENTAL_ONLY_STEMS`» и пересборка `_STOP_PATTERNS` должна ронить новый тест.

### 2. При ошибке картинки у края лимита фронтенд не показывает «картинка не создана из-за лимита» и запускает отдельный `/generate-image-from-text/`

- **Серьёзность:** мелочь (критерий промпта «понятная пометка в теле ответа» выполнен; пометка просто не выходит на экран).
- **Доказательство:**
  - `generator/views.py:291, 357` — при `GigaChatError` в цепочке картинки `/generator/` ставит `image_error = e.message` и возвращает JSON `{'success': True, 'result': ..., 'image_url': null, 'image_error': 'Лимит токенов GigaChat исчерпан. Генерация недоступна.', ...}`. Тест `ChainWithImageNearLimitTests.test_image_error_message_mentions_limit` это проверяет.
  - `generator/templates/generator/gigagenerator.html:470–520` — ветка успеха: `const wantImage = ...checked;`, `var hasImage = data.image_url && ...`. На ответе выше `hasImage === false`, `wantImage === true`, `data.result` непустой → `if (wantImage && data.result && !hasImage)` на `:517` запускает **второй запрос** `/generate-image-from-text/` с текстом поста. На сервере этот запрос снова упрётся в лимит в `check_gigachat_access` (`access.py:193` → 429 `MSG_TOKEN_LIMIT`). `image_error` в DOM нигде не используется (grep: `image_error` появляется только в `views.py`).
- **Сценарий сбоя:** посетитель у края лимита нажимает «Сгенерировать» с галочкой «Сделай картинку»: получает текст + индикатор «Генерация изображения…» + второй AJAX, второй отвечает 429 с текстом «Лимит генераций для вашего доступа исчерпан.» (другое, не `image_error`) → в тосте появляется это сообщение, а не исходная «картинка пропущена из-за лимита токенов GigaChat». UX сбивается, пользователь видит сначала «идёт генерация картинки», потом «лимит исчерпан» вообще без указания, что текст уже спасён. Серверная цепочка в этом втором запросе не выполняет вызова GigaChat (`check_gigachat_access` отсекает до клиента), поэтому утечки токенов нет.

- **Как проверить:** тест разметки — такой же, как `ServerTextMarkupTests`, но на поиск строки `image_error` в `gigagenerator.html`; плюс можно добавить unit-тест на серверной стороне, что `data.image_error` показывается через `data-testid` в блоке карточки изображения (это требует правок разметки — выходит за объём фазы). Короче — обойтись проверкой руками в фазе 5 или в фазе 2а.3 при верстке; критерий фазы 2а.1 выполнен.

### 3. `test_showtoast_uses_textcontent` захватывает только начальный блок тела `showToast`

- **Серьёзность:** мелочь.
- **Доказательство:** `tests/test_post_quality.py:1256` — regex `r'function\s+showToast[^{]*\{(.*?)^\s*\}'` c `re.DOTALL | re.MULTILINE`, минимальное `(.*?)`. У обоих `showToast` (`index.html:821–852`, `gigagenerator.html:626–651`) внутри тела есть `if/else`-блоки с закрывающими `}` на отдельной строке с пробелами. Regex остановится на **первом** таком `}`, т.е. захватит только тело ветки `if (window.bootstrap)` / `if (toastContainer && toast)`. На нынешнем коде этого достаточно (`innerHTML` ушёл именно из этой ветки), но тест формально не проверяет «нет `innerHTML` во всей функции».
- **Сценарий сбоя:** если позже кто-то добавит `innerHTML` в ветку `else { ... }` функции `showToast` в `gigagenerator.html`, тест этого не поймает.
- **Что изменить:** переписать захват функции через подсчёт скобок (например, вспомогательной функцией в тесте) или воспользоваться уже написанной регуляркой `SUSPICIOUS_INTERP_RE` + `EMPTY_CLEAR_RE` на вес файл, а в тесте оставить только assert «в теле `showToast` нет `innerHTML` с какой-либо переменной».
- **Как проверить:** добавить в `showToast` временно строку `foo.innerHTML = msg` в ветке `else` → тест должен падать (сейчас — пройдёт).
