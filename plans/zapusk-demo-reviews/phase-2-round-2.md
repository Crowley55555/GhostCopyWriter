### 2. Поиск штампов срабатывает на обычных фразах

- **Серьёзность:** мелочь. `find_stop_phrases` используют только тесты и скрипт прогона. Если на ней построить вариант 1(б), это станет важно.
- **Доказательство.** `_stop_phrase_pattern` (`generator/gigachat_api.py:389–405`). Пробы в копии — 8 ложных срабатываний из 16 обычных фраз:

  | Фраза | Найдено |
  |---|---|
  | «Индивидуальные занятия подходят тем, кто стесняется группы.» | «индивидуальный подход» |
  | «Индивидуальная программа подходит даже новичкам.» | «индивидуальный подход» |
  | «В нашей студии время пролетает незаметно.» | «в наше время» |
  | «В нашей пекарне время замеса — двенадцать часов.» | «в наше время» |
  | «На новых тренажёрах уровень нагрузки меняется кнопкой.» | «на новый уровень» |
  | «Хотите узнать про боль в спине? Приходите на консультацию.» | «хотите узнать больше?» |

  Причины две:
  - **Короткие основы** (`:403`):
    - «подход» → `подх\w*` (подходит, подходят);
    - «больше» → `боль\w*`;
    - «цены» → `цен\w*` (ценителям);
    - «заряд» → `заря\w*` (зарядка).
  - **Любое вставленное слово между словами штампа** (`:405`): «в нашей **студии** время», «на новых **тренажёрах** уровень».

  `test_near_stamps_not_detected` проверяет 4 фразы, и все они проходят. Для полноты — два пропуска: «Выйти на новом уровне» → `[]` («новый» → `новы\w*`) и «Хочешь узнать о нас больше?» → `[]` (два вставленных слова; так задумано).

- **Что исправить.**
  - Вставленное слово разрешать только из короткого списка: свой, свою, свои, ваш…, наш…, этот, эту, эти. Этого хватает для проб ревью («не упустите **свой** шанс», «в **нашем** современном мире») и убирает все 8 срабатываний выше.
  - Основу брать отбрасыванием типичного окончания, а не фиксированного числа букв.
- **Как проверить.**
  - 8 фраз выше добавлены в `test_near_stamps_not_detected` и возвращают `[]`.
  - `REQUIRED_STAMPS`, 4 фразы ревью и штампы постов 2, 6, 7 («заряжает энергией», «зарядиться энергией», «увлекательному миру», «индивидуальный подход») по-прежнему находятся.

### 3. Постобработка: остаточные ложные срезы на редких формулировках

- **Серьёзность:** мелочь. В 28 живых ответах постобработка ничего не срезала. Формулировки ниже при нынешнем промпте маловероятны, но если они встретятся, текст пропадёт без всякой ошибки.
- **Доказательство** — `postprocess_final_result` в копии:
  - **Первая строка с «вариант».** «Вот несколько вариантов осеннего ухода:», «Вот вариант завтрака для тех, кто спешит:», «Хорошо, когда есть варианты на любой вкус:» удаляются как вступление. Причина — `_INTRO_RE` (`gigachat_api.py:540–544`): `вариант\w*` целым словом совпадает и в обычной первой строке. Пост начинается с «— маска раз в неделю;» или «сырник и капучино с собой.».
  - **Ответ без пустых строк.** «Хлеб на закваске / Этот текст написан для тех, кто выбирает хлеб в магазине. / Закваска — живая культура. / А вы какой хлеб берёте?» превращается в «Хлеб на закваске». Без пустых строк последним абзацем считается весь ответ, кроме первой строки (`:612`, спорное решение исполнителя 2). Тот же текст с пустыми строками остаётся целым.
  - **«Финальный результат:» отдельной строкой.** В посте «до/после» («Было: сухие кончики. / Финальный результат: / блестящие волосы…») всё до этой строки и она сама срезаются (`:537`, `:585–588`).
  - **Заголовок Дзена «Пост: …».** «Пост: какой хлеб можно есть» превращается в «какой хлеб можно есть». `_LABEL_RE` (`:528`) снимает «Пост:» и «Текст:» в любой строке (`:623`).
  - **«Надеюсь, этот пост…» с вопросом.** Последний абзац «Надеюсь, этот пост поможет выбрать напиток. А вы какой берёте?» срезается целиком, вместе с вопросом читателям. Так работает правило из задания; случай спорный.
- **Сценарий сбоя.** Пост-подборка ВКонтакте (формат «Списки») начинается со строки «Вот три варианта осеннего ухода:». Пользователь получает пост без вводной строки, который начинается с тире.
- **Что исправить** — на выбор судьи, приоритет у первых двух:
  - вступление с «вариант…» срезать, только если следующая строка с текстом — метка «Вариант 1» или если «вариант» стоит рядом с «поста», «текста», «статьи»;
  - если в ответе нет пустых строк, последним абзацем считать последнюю строку;
  - маркер «Финальный результат» срезать, только если в ответе есть другие признаки старого формата («Агент…:», «Критик:»);
  - метки «Пост:» и «Текст:» снимать только в первой строке с текстом.
- **Как проверить.**
  - Пробы выше добавлены в `PostprocessTests` и дают пост целиком.
  - `test_variants_after_intro` по-прежнему отдаёт «Первый пост.».
  - Остальные тесты постобработки зелёные.
