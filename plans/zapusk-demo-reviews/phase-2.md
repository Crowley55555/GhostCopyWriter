## Замечания

### 1. Постобработка срезает обычный текст поста

- **Серьёзность:** важно.
- **Доказательство.** Четыре места в `generator/gigachat_api.py`:
  - `:512`, `:554–557`: маркер старой преамбулы `_OLD_FINAL_RE = 'финальный результат'` ищется через `search` в любой строке, а не только в строке, где стоит один маркер. Всё до этой строки и она сама выбрасываются.
  - `:520–528`, `:573–577`: `_TAIL_RE` срезает ответ до конца с любой строки, кроме первой, если она начинается с «Этот/Данный пост|текст», «Надеюсь, этот|пост|текст» или «Агент…:» (`агент[\w\s-]*` ловит и «Агентство недвижимости:»).
  - `:514–516`, `:562–564`: `_INTRO_RE` ищет «пост|текст|вариант|стать» как подстроку. Под неё попадают «**пост**упил» и «о**стать**ся», и тогда удаляется первая строка поста.
  - `:530`, `:567–570`: строки «Вариант 1:» и «Вариант 2:» внутри поста-сравнения (формат «Сравнение»: «один вариант против другого») оставляют только текст первого варианта.

  Пробы. Вход → результат `postprocess_final_result`, строки ввода разделены знаком « / »:

  | Вход | Результат |
  |---|---|
  | «Осенний уход за волосами / Сухие кончики — частая история после лета. / Финальный результат зависит от домашнего ухода: маска раз в неделю. / А как вы ухаживаете за волосами?» | `'А как вы ухаживаете за волосами?'` — заголовок и два абзаца потеряны |
  | «Чем хлеб на закваске отличается от обычного / Этот текст — для тех, кто выбирает хлеб в магазине и читает состав. / Закваска — это живая культура. / А вы какой хлеб берёте?» | `'Чем хлеб на закваске отличается от обычного'` — от статьи Дзена остался только заголовок |
  | «Ноутбук греется и шумит? / Скорее всего, пора на чистку. / Надеюсь, этот совет сбережёт ваш ноутбук. Как давно вы его чистили?» | последний абзац с вопросом к читателям потерян |
  | «Вот и поступил в меню наш осенний раф: / облепиха, мёд и немного корицы. / Заходи попробовать!» | первая строка удалена, пост начинается с «облепиха, мёд…» |
  | «Ищете квартиру? / Агентство недвижимости: такие вопросы решаем за день. / Пишите в сообщения.» | всё после первой строки срезано |
  | «Летняя или зимняя? / Вариант 1: / Липучка — для города. / Вариант 2: / Шипы — для трассы. / Какую выбираете?» | `'Липучка — для города.'` |

- **Сценарий сбоя.** Пост салона, мастера маникюра или ремонта содержит «финальный результат…». Или статья Дзена начинается после заголовка со слов «Этот текст — о том…». Пользователь без всякой ошибки получает обрубок: на показе это одна строка заголовка (принципы 2 и 5). Тест `test_word_ocenka_in_post_kept` закрывает только слово «Оценка». Эти фразы он не покрывает.
- **Что исправить.**
  - Старый маркер срезать, только когда строка целиком — «Финальный результат», с возможными `*`, `#`, `:` (например, `^\W*финальный результат\W*$`).
  - Пояснения после поста срезать только в последнем абзаце и только когда он говорит о самом посте: «этот пост/текст подчёркивает, написан, составлен…». Обычное «Этот текст — для тех…» и «Надеюсь, этот совет…» внутри поста не трогать.
  - «Агент…» срезать только в старом формате, например `^Агент(?:-\w+)?\s*\d*\s*:`.
  - Во вступлении искать слова целиком (`\b(?:пост|поста|текст|вариант\w*|стать[яюи])\b`), а не подстроки.
  - Варианты резать, только если «Вариант 1» — первая строка ответа с текстом.
- **Как проверить.** Добавить пробы из таблицы в `PostprocessTests`: на выходе полный пост, а для случая с метками вариантов — согласованное ожидание. Существующие тесты постобработки остаются зелёными. Мутация «снова `search` по любой строке» должна валить новый тест.

### 2. Проверка штампов не видит формы на «ты» и вставленные слова

- **Серьёзность:** мелочь.
- **Доказательство.** `generator/gigachat_api.py:366–391` (`_stop_phrase_pattern`, `find_stop_phrases`):
  - «Окунись в атмосферу осени» → `[]`;
  - «Хочешь узнать больше? Пиши!» → `[]`;
  - «Не упустите свой шанс» → `[]`;
  - «В нашем современном мире» → `[]`.

  Формы на «вы» находятся. «Не упусти шанс» тоже находится.
- **Сценарий сбоя.** Прогон 10 тем проверяет штампы этой функцией. У темы 2 (кофейня) в «О бизнесе» сказано «пишем на «ты»». Модель пишет «Окунись в атмосферу осени», а в `phase-2-samples.md` попадает «Штампы: нет». Критерий 2 из `idea/mvp.md` проверяется не полностью. Запрет в промпте при этом есть: «Их перефразировки тоже не подходят».
- **Что исправить.** Добавить в `STOP_PHRASES` формы на «ты» («окунись в атмосферу», «хочешь узнать больше») или укоротить основы глаголов. Между словами штампа допускать одно слово: `(?:\s+\w+)?`.
- **Как проверить.** Четыре строки выше в `StopPhrasesTests` находятся. `test_clean_post` не даёт ложных срабатываний.

## Спорные решения исполнителя

1. **Ошибка формы для AJAX — 400 вместо 200.** Согласен. Это согласуется с правилом фазы 1 «слишком длинный ввод — 400». Фронтенд разбирает JSON при любом коде (`gigagenerator.html`, обработчик `submit`).
2. **Перегенерация не берёт тему из POST.** Согласен: так требует пункт 5 задания. Заметка для фазы 5: если пользователь изменил тему в поле, перегенерация молча повторит прежнюю. Кнопке нужна подпись или подсказка.
3. **Значения по умолчанию подставляет форма, а не сборка промпта.** Согласен. Они попадают в `last_form_data`, поэтому перегенерация и промпт картинки видят те же значения. `generate_text` в `generator/` вызывают только эти два view.
4. **Длина и хэштеги — настройки со своими значениями по умолчанию для каждой площадки, а не числа в `PLATFORM_RULES`.** Согласен. Одна оговорка: если для Дзена явно выбрать «Очень короткий», это спорит с правилом «вступление, 2–4 смысловых блока». Это явный выбор пользователя, не дефект.
5. **`find_stop_phrases` лежит в `gigachat_api`.** Согласен. О полноте поиска — замечание 2.
6. **Поле темы — 3 строки, выбор генератора остался вне «Дополнительно».** Согласен: OpenAI снимает фаза 4.
7. **Без отдельного номера: «13 настроек» плана — это 12 настроек плюс `platform_specific`.** Согласен. Место `platform_specific` заняло обязательное поле площадки.
