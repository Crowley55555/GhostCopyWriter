## Что исправить (сначала падающий тест, потом код)

### 1. Постобработка срезает обычный текст поста (важно)

`postprocess_final_result` и связанные регулярные выражения в `generator/gigachat_api.py`. Сделай по предложениям из отчёта ревьюера:

- маркер «Финальный результат» срезать, только когда строка целиком — этот маркер (допустимы `*`, `#`, `:` и пробелы вокруг);
- пояснение после поста срезать только в **последнем** абзаце и только когда оно говорит о самом посте («этот пост/текст подчёркивает, написан, составлен…»). Обычные «Этот текст — для тех…» и «Надеюсь, этот совет…» внутри поста не трогать;
- «Агент…» срезать только в старом формате (например, `^Агент(?:-\w+)?\s*\d*\s*:`), чтобы не задевать «Агентство недвижимости:»;
- во вступлении искать слова целиком (`\b…\b`), а не подстроки: «поступил» и «остаться» не должны совпадать;
- метки «Вариант 1:» и «Вариант 2:» обрабатывать, только если «Вариант 1» — первая строка ответа с текстом. Пост-сравнение с вариантами внутри сохраняется целиком.

**Тесты.** Все шесть проб из таблицы замечания 1 добавь в `PostprocessTests`. На выходе — полный пост. Для случая с вариантами — пост целиком. Существующие тесты постобработки остаются зелёными.

**Проверка мутацией.** Временно верни поиск маркера по любой строке (`search` вместо проверки строки целиком), убедись, что новый тест падает, верни код. Сверь `git diff`: следов мутации нет.
